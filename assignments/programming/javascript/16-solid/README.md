# Принципы ООП — SOLID

**S** — Single Responsibility Principle; **O** — Open/Closed Principle; **L** — Liskov Substitution Principle; **I** — Interface Segregation Principle; **D** — Dependency Inversion Principle.

Все пять применимы на практике как ориентиры для снижения связанности и повышения изменяемости, но не должны превращаться в самоцель. В отличие от общих KISS/DRY/YAGNI, SOLID сфокусирован прежде всего на проектировании модулей, объектов и зависимостей.

Наиболее сложным часто оказывается **LSP**: подтип должен сохранять ожидания контракта базового типа, а не только совпадать по сигнатурам. Например, если `PaymentMethod.pay()` по контракту либо успешно платит, либо выдаёт доменную ошибку, реализация не должна тихо возвращать `undefined` или менять единицы суммы.

`example.mjs` показывает SRP/OCP/DIP через стратегию скидки и checkout.
