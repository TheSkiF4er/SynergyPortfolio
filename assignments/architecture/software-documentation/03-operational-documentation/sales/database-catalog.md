# Каталог базы данных — АС «Отдел продаж»

## Назначение
Каталог фиксирует логическую структуру основной реляционной базы данных АС «Отдел продаж». Типы приведены как рекомендуемые SQL-типы; физическая схема может уточняться при проектировании.

| Таблица | Назначение | Ключевые атрибуты |
| --- | --- | --- |
| customers | Покупатели | id PK; name varchar(255); tax_id varchar(32); status varchar(20) |
| products | Товары | id PK; sku varchar(64) UNIQUE; name varchar(255); price decimal(14,2); is_active boolean |
| sales_orders | Заказы | id PK; number varchar(64) UNIQUE; customer_id FK; manager_id FK; order_date date; status varchar(20); total decimal(16,2) |
| order_items | Позиции заказа | id PK; order_id FK; product_id FK; quantity decimal(14,3); price decimal(14,2); discount decimal(5,2) |
| invoices | Счета | id PK; order_id FK; number varchar(64); issued_at date; due_at date; amount decimal(16,2); status varchar(20) |

## Правила целостности
- каждый первичный ключ `id` уникален и не изменяется после создания;
- внешние ключи должны ссылаться только на существующие активные/исторические записи согласно бизнес-правилам;
- денежные и количественные значения хранятся в `decimal`, а не `float`;
- даты операций сохраняются отдельно от системного времени создания записи, если эти значения различаются;
- удаление значимых бизнес-объектов выполняется логически либо ограничивается при наличии зависимостей;
- изменения критичных сущностей журналируются.

## Связи
- `sales_orders` содержит внешние ключи, связывающие запись с родительскими сущностями предметной области.
- `order_items` содержит внешние ключи, связывающие запись с родительскими сущностями предметной области.
- `invoices` содержит внешние ключи, связывающие запись с родительскими сущностями предметной области.

## Резервирование и доступ
База данных резервируется по регламенту организации. Прямой доступ конечных пользователей к СУБД запрещён; работа выполняется через прикладной API. Учётная запись приложения имеет только необходимые права.
