# Каталог базы данных — АС «Бухгалтерия»

## Назначение
Каталог фиксирует логическую структуру основной реляционной базы данных АС «Бухгалтерия». Типы приведены как рекомендуемые SQL-типы; физическая схема может уточняться при проектировании.

| Таблица | Назначение | Ключевые атрибуты |
| --- | --- | --- |
| accounts | План счетов | id PK; code varchar(16) UNIQUE; name varchar(255); type varchar(20); is_active boolean |
| counterparties | Контрагенты | id PK; name varchar(255); tax_id varchar(32); kind varchar(20) |
| documents | Первичные документы | id PK; number varchar(64); document_date date; kind varchar(32); counterparty_id FK; amount decimal(16,2); status varchar(20) |
| postings | Проводки | id PK; document_id FK; debit_account_id FK; credit_account_id FK; amount decimal(16,2); posted_at timestamp |
| periods | Учётные периоды | id PK; year int; month int; status varchar(20); closed_at timestamp |

## Правила целостности
- каждый первичный ключ `id` уникален и не изменяется после создания;
- внешние ключи должны ссылаться только на существующие активные/исторические записи согласно бизнес-правилам;
- денежные и количественные значения хранятся в `decimal`, а не `float`;
- даты операций сохраняются отдельно от системного времени создания записи, если эти значения различаются;
- удаление значимых бизнес-объектов выполняется логически либо ограничивается при наличии зависимостей;
- изменения критичных сущностей журналируются.

## Связи
- `documents` содержит внешние ключи, связывающие запись с родительскими сущностями предметной области.
- `postings` содержит внешние ключи, связывающие запись с родительскими сущностями предметной области.

## Резервирование и доступ
База данных резервируется по регламенту организации. Прямой доступ конечных пользователей к СУБД запрещён; работа выполняется через прикладной API. Учётная запись приложения имеет только необходимые права.
