# Каталог базы данных — АС «Клиенты»

## Назначение
Каталог фиксирует логическую структуру основной реляционной базы данных АС «Клиенты». Типы приведены как рекомендуемые SQL-типы; физическая схема может уточняться при проектировании.

| Таблица | Назначение | Ключевые атрибуты |
| --- | --- | --- |
| clients | Клиенты | id PK; type varchar(20); name varchar(255); tax_id varchar(32); status varchar(32); created_at timestamp |
| contacts | Контакты | id PK; client_id FK; kind varchar(20); value varchar(255); is_primary boolean |
| interactions | Взаимодействия | id PK; client_id FK; channel varchar(20); happened_at timestamp; subject varchar(255); result text; manager_id FK |
| segments | Сегменты | id PK; code varchar(32) UNIQUE; name varchar(120); description text |
| client_segments | Связь клиент-сегмент | client_id FK; segment_id FK; assigned_at timestamp |

## Правила целостности
- каждый первичный ключ `id` уникален и не изменяется после создания;
- внешние ключи должны ссылаться только на существующие активные/исторические записи согласно бизнес-правилам;
- денежные и количественные значения хранятся в `decimal`, а не `float`;
- даты операций сохраняются отдельно от системного времени создания записи, если эти значения различаются;
- удаление значимых бизнес-объектов выполняется логически либо ограничивается при наличии зависимостей;
- изменения критичных сущностей журналируются.

## Связи
- `contacts` содержит внешние ключи, связывающие запись с родительскими сущностями предметной области.
- `interactions` содержит внешние ключи, связывающие запись с родительскими сущностями предметной области.
- `client_segments` содержит внешние ключи, связывающие запись с родительскими сущностями предметной области.

## Резервирование и доступ
База данных резервируется по регламенту организации. Прямой доступ конечных пользователей к СУБД запрещён; работа выполняется через прикладной API. Учётная запись приложения имеет только необходимые права.
