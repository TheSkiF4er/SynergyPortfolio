# Каталог базы данных — АС «Склад»

## Назначение
Каталог фиксирует логическую структуру основной реляционной базы данных АС «Склад». Типы приведены как рекомендуемые SQL-типы; физическая схема может уточняться при проектировании.

| Таблица | Назначение | Ключевые атрибуты |
| --- | --- | --- |
| warehouses | Склады | id PK; name varchar(120); address varchar(255); is_active boolean |
| products | Номенклатура | id PK; sku varchar(64) UNIQUE; name varchar(255); unit varchar(16); min_stock decimal(14,3) |
| stock_items | Остатки | warehouse_id FK; product_id FK; quantity decimal(14,3); reserved decimal(14,3) |
| stock_movements | Движения | id PK; type varchar(20); warehouse_id FK; product_id FK; quantity decimal(14,3); occurred_at timestamp; document_no varchar(40) |
| inventories | Инвентаризации | id PK; warehouse_id FK; started_at timestamp; closed_at timestamp; status varchar(20) |

## Правила целостности
- каждый первичный ключ `id` уникален и не изменяется после создания;
- внешние ключи должны ссылаться только на существующие активные/исторические записи согласно бизнес-правилам;
- денежные и количественные значения хранятся в `decimal`, а не `float`;
- даты операций сохраняются отдельно от системного времени создания записи, если эти значения различаются;
- удаление значимых бизнес-объектов выполняется логически либо ограничивается при наличии зависимостей;
- изменения критичных сущностей журналируются.

## Связи
- `stock_items` содержит внешние ключи, связывающие запись с родительскими сущностями предметной области.
- `stock_movements` содержит внешние ключи, связывающие запись с родительскими сущностями предметной области.
- `inventories` содержит внешние ключи, связывающие запись с родительскими сущностями предметной области.

## Резервирование и доступ
База данных резервируется по регламенту организации. Прямой доступ конечных пользователей к СУБД запрещён; работа выполняется через прикладной API. Учётная запись приложения имеет только необходимые права.
