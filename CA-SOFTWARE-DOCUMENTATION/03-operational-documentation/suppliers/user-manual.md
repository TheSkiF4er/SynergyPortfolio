# Руководство пользователя — АС «Поставщики»

## 1. Введение

### 1.1 Область применения
АС «Поставщики» предназначена для автоматизации процессов: ведение поставщиков, договоров, поставок и оценки качества исполнения. Настоящее руководство описывает работу пользователей через web-интерфейс системы.

### 1.2 Возможности
- авторизация и разграничение прав по ролям;
- ведение основных справочников и рабочих документов;
- поиск, фильтрация и просмотр истории изменений;
- формирование регламентированной и оперативной отчётности;
- экспорт разрешённых выборок;
- аудит критичных пользовательских действий.

### 1.3 Уровень подготовки пользователей
Пользователь должен владеть базовыми навыками работы с персональным компьютером и браузером, понимать терминологию предметной области и пройти первичный инструктаж по информационной безопасности.

### 1.4 Эксплуатационная документация
В комплект входят это руководство, «Массив выходных данных», «Каталог базы данных» и «Состав выходных данных».

## 2. Назначение и условия применения

### 2.1 Функции
Ведение поставщиков, договоров, поставок и оценки качества исполнения. Система обеспечивает единый источник данных, журналирование действий и формирование отчётных представлений.

### 2.2 Роли
| Роль | Полномочия |
| --- | --- |
| Специалист по закупкам | карточки поставщиков, договоры и поставки |
| Руководитель закупок | согласование и аналитика |
| Контролёр качества | оценка качества поставок |
| Администратор | пользователи и справочники |

### 2.3 Программные и аппаратные условия
- современный браузер с поддержкой TLS 1.2+ и JavaScript;
- разрешение экрана от 1280×720, для мобильного режима — от 360 px;
- стабильное подключение к корпоративной сети;
- серверная часть: Linux, reverse proxy, прикладной сервис и реляционная СУБД;
- резервное копирование БД не реже одного раза в сутки.

## 3. Подготовка к работе

### 3.1 Состав поставки
Серверное приложение, конфигурация окружения, схема БД/миграции, инструкции администратора и пользовательская документация.

### 3.2 Первый запуск пользователя
1. Получить учётную запись у администратора.
2. Открыть адрес системы по HTTPS.
3. Ввести логин и пароль.
4. При первом входе сменить временный пароль.
5. Проверить отображаемую роль и доступные разделы.

### 3.3 Проверка работоспособности
После входа должны загрузиться главная страница и доступные пользователю разделы без ошибок. При отсутствии ожидаемых прав следует обратиться к администратору, не создавая повторную учётную запись.

## 4. Описание операций

| № | Операция | Результат/действия |
| --- | --- | --- |
| 1 | Регистрация поставщика | Создать карточку, заполнить реквизиты и контактное лицо. |
| 2 | Создание договора | Выбрать поставщика, указать номер, срок и сумму, сохранить договор. |
| 3 | Регистрация поставки | Привязать поставку к договору, указать дату, сумму и статус. |
| 4 | Оценка поставки | После закрытия поставки указать оценки качества и своевременности. |
| 5 | Блокировка поставщика | Изменить статус с фиксацией причины и пользователя. |
| 6 | Рейтинг поставщиков | Задать период и сформировать рейтинг по качеству/срокам. |

Для операций изменения данных система должна показывать результат сохранения. Критичные действия должны фиксироваться в журнале аудита с пользователем и временем выполнения.

## 5. Аварийные ситуации

| Ситуация | Действия пользователя |
|---|---|
| Система недоступна | Проверить сеть и адрес; повторить попытку; сообщить администратору время и текст ошибки. |
| Ошибка 401/403 | Выполнить повторный вход; при сохранении ошибки запросить проверку роли. |
| Ошибка сохранения | Не дублировать операцию до проверки результата; зафиксировать номер документа/время. |
| Потеря соединения во время операции | После восстановления соединения проверить фактический статус объекта перед повторным действием. |
| Некорректные данные | Не исправлять напрямую в БД; использовать предусмотренную операцию корректировки либо обращение администратору. |

## 6. Рекомендации по освоению

1. Начать с поиска и просмотра существующих записей.
2. Выполнить учебное создание объекта в тестовой среде.
3. Освоить фильтры и экспорт.
4. Изучить правила изменения/отмены документов.
5. Перед массовыми операциями использовать тестовый набор данных.

## 7. Безопасность

Пароли не передаются другим пользователям. Рабочая сессия блокируется при уходе от рабочего места. Экспортированные данные хранятся только в разрешённых корпоративных каталогах. Доступ предоставляется по принципу минимально необходимых полномочий.
