# Принципы написания кода

Разные принципы существуют потому, что разработка постоянно балансирует понятность, скорость изменений, повторное использование и сложность. Они защищают от дублирования, преждевременной архитектуры, чрезмерной связанности и трудно читаемого кода.

На практике особенно полезны **KISS**, **DRY** и **YAGNI**: простое решение легче проверить; повторяющееся знание стоит централизовать; ненужную будущую функциональность не следует проектировать заранее. При этом DRY не означает «устранить любое одинаковое выражение»: важнее не дублировать одно и то же бизнес-знание.

Критичные различия: KISS — про простоту, DRY — про единственный источник знания, YAGNI — про отказ от неподтверждённых требований, SOLID — про дизайн зависимостей/объектов. Разработчики формулируют такие принципы, чтобы команда имела общий язык для trade-off решений.
